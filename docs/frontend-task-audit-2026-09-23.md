## 优先级最高的缺口

1. **T-09 退回后的编辑与重新提交（P0）**：`pages/community/my-content/index.wxml:107–114` 只提供申诉；事件处理在 `pages/community/my-content/index.js:201–217` 进入申诉页。发布页只恢复 `draftId`（`pages/release/index.js:121–150`），`services/posts.js:34–42` 只有创建内容的 `POST /posts`。请先由前后端确定“编辑原退回内容”的版本、幂等与审计语义；再做编辑器入口、草稿恢复和重提验收。申诉不能替代重提。
2. **T-14b 头像上传（P1，能力保持关闭）**：`pages/my/info-edit/index.js:39–45` 和 `services/profiles.js:11–13` 明确只有昵称保存。应在后端头像资产审核/绑定契约就绪后独立接入，不要把图片帖子上传误当头像已支持。
3. **T-02b 组件接入（P1）**：`components/post-card/index.wxml:3–50` 仍内联作者/媒体渲染；`identity-label` 与 `media-preview` 没在 `post-card` 注册或使用。可独立替换并保留 `tapauthor / tapmedia` 等现有事件，随后做组件交互检查。
4. **统一列表错误态（P1，小而独立）**：`pages/topics/index.js:36–43`、`pages/message/index.js:28–35`、`pages/search/index.js:75–87` 在请求失败时保留旧数据；各自 WXML 的列表优先分支（话题 `pages/topics/index.wxml:25–43`、消息 `pages/message/index.wxml:19–47`、搜索 `pages/search/index.wxml:54–77`）会盖住错误提示和重试入口。应在旧数据保留时显示“未更新 + 重试”，无旧数据时显示整页错误态。
5. **角色验收矩阵（P0 上线前）**：`mock/community/index.js:10` 当前固定 `MOCK_ROLE = 'member'`；测试只覆盖若干静态门控/单个会话失效场景。现有云端记录是单个 moderator 调试账号，尚无访客、成员 A、成员 B、被移除成员与 moderator 的跨账号矩阵，更没有 `docs/10` 要求的三角色 × 18 页记录。至少记录各角色在信息流、搜索、私密深链、匿名作者、主页和管理深链的结果；页面存在或单账号截图都不算通过。
6. **T-17 错误种类验收（P1）**：`api/request.js:22–55` 定义 HTTP/业务码映射与默认提示，但项目没有逐类 UI 验收报告；先覆盖 `unauthenticated / membership_invalid / forbidden / not_accessible / invalid_input / conflict / pending_media / rate_limited / network / timeout / server` 的页面动作，再据实更新 T-17。契约把 network 与 timeout 合并描述，因此实际是 11 个 kind，不能将其压成十种而漏测一种。
